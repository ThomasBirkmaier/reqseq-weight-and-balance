title: Counting of the project limits
rationale: The project procedure names the supplier only in the limit for system requirements (supplier included), and gives the supplier a limit of its own for its system requirements, so that limit is a total of both workspaces; for every other element type the supplier keeps a workspace of its own with its own stakeholders, needs, decisions and glossary. The procedure removes an element at a limit by superseding it, so a superseded element no longer counts. This rationale is the reading of the requirements role; IV&V confirms it.
---

The limits of the project count as follows:

- Stakeholders, needs, hazards, decisions and glossary terms count per workspace: this workspace and the supplier's workspace (`fuel`) each stay within the limit on their own.
- System requirements count both workspaces together.
- An element with an invalid status (obsolete) does not count.

This rule was part of the scope of release 2 until release 3.
