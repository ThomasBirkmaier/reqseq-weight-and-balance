title: Technology of the system
rationale: "Constraint of the client frame: a static web app is free to host, needs no installation and works on the pilots' phones; a typed core compiled to WebAssembly keeps the calculation separate from the user interface and testable on its own."
---

Constraint: the calculation core is written in Rust and compiled to WebAssembly (`wasm32-unknown-unknown`, no external crates); the user interface is TypeScript with SVG graphics; the system is a static web app hosted on GitHub Pages. Unit tests run with `cargo nextest`, end-to-end tests with Playwright, both writing JUnit XML.

System boundary:

- Pilot ↔ app: the pilot opens the web address in the browser of a phone or computer, selects the aircraft, enters the loading and reads the results on the screen. "The app" in acceptance criteria means the system as the pilot sees it.
- Maintenance organisation ↔ app: the released empty mass, empty-mass lever arm and weighing date of each aircraft are recorded in one fleet data file in the repository (`data/fleet.csv`, one line per aircraft); a change of this file reaches the pilots with the next published build.
- Network: the app loads its files from its web address; it sends no entered value anywhere, and after the first visit it opens from the browser cache without network.
- Variants are separate builds: the core build for the HC-4 fleet at the root of the web address, the HC-2 build below `hc2/`.
