title: Decisions as origin of requirements
rationale: The project procedure allows a requirement to derive from a decision, but forbids giving a relation of the standard model a meaning it does not have. The chain from a hazard or a need to its requirements must still show every origin.
---

The pilot extension of the standard model (`spec/metamodel/pilot-model.yaml`) adds the relation kind `originates-from` (Originates from, inverse Origin of) from System Requirement to Decision with the meaning `derivation`.

- A system requirement whose origin is a decision and not a need names that decision with `originates-from`. A chain then follows it from the requirement to the decision, and the requirement has a parent.
- `based-on` keeps the meaning of the standard model: the source rests on a decision. It carries no derivation; a requirement that derives from a need names the decisions it rests on with `based-on`.
- The relations of the standard model are not changed: `spec/metamodel/standard-model.yaml` is the file that `reqseq workspace init` writes. Release 1 had given `based-on` the meaning derivation; that change is removed.
- The supplier workspace uses copies of both metamodel files, so that every element has the same version in both workspaces.
