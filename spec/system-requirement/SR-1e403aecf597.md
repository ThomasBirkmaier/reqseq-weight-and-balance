title: Data file not readable in its documented form
rationale: A data file that is read in part or against its documented form gives limit indications from wrong data; the pilot must see that the app has no data instead. The parser rules (duplicate member names, numbers out of range, missing fields) were hardened in release 2 without a requirement.
requirement-type: interface
acceptance-criteria:
  - key: stzd
    text: Given a fuel interface data file in which a member name appears twice in one object (for example the aircraft HC4-01 twice) or a number is out of its documented range (for example a fuel lever arm of 99999999999999999 m), when the app is built from it and opened, then it offers no aircraft for selection and shows "The app could not load its data. Reload the page."
  - key: t42r
    text: Given a fleet data file with the line `HC4-01,hc4,765` without empty-mass lever arm and weighing date, or with an unknown aircraft type, when the app is built from it and opened, then it offers no aircraft for selection and shows "The app could not load its data. Reload the page."
  - key: n6bb
    text: Given the calculation core of the app cannot be loaded or answers with data of an unexpected form, when the pilot opens the app of either build, then it shows "The app could not load its data. Reload the page." and no aircraft selection.

If a data file of the build is not readable in its documented form, the system shall show the message "The app could not load its data. Reload the page." instead of the aircraft selection.
